# 教材 → クリップ台本：エージェントワークフロー

## 入口と成果物
対象は The Annotated World の既存教材。新規教材の作成、動画生成、配信は別工程。Pilot 013 の本人評価「めっちゃいいね」を編集・演出の基準にし、Studio v2を使用する。依頼が「クリップの台本を作って」「教材からショートを作って」ならここから始める。台本だけの依頼では動画を生成しない。

入力は教材 slug、任意の章ID・論点・件数。指定なしなら公開教材を列挙し、未使用の有望な論点を選ぶ。公開教材の存在は原典録音の確認や再利用権を意味しない。自動投稿・定期実行・新規外部APIキーは要求しない。

正本は productions/<clip-id>/brief.json（Studio v2形式）。台本と映像指示をまとめ、editorial.scriptReview に選定・反証の結果を記録する。script.md は JSON から生成する閲覧用の台本で、編集正本を二重化しない。素材や権利が未確認なら明記し、未許諾の素材を配信・公開Gitに追加しない。実音声・画像は台本段階では不要。

## 1. 素材を集める — Researcher
```sh
npm run content:inspect
npm run --silent short:script:prepare -- <slug> [--chapter ch10]
```
prepare は教材情報・原典来歴・章索引・候補英文・注釈・前後発話・既存briefの使用箇所を返す。指定章は全発話を収録する。キーワード候補が少なくても章本文を読む。候補スコアは選定の代替ではない。

原典の発言者・相手の質問・前後の留保・実際の時刻を確かめる。既存コンテンツの原文を唯一の引用元とし、外部史料は編者註の裏付けに使う。原音声未照合は未照合のまま。個々の引用は固定 chapterId/utteranceId/time と逐語英文を保持。転載制約がある原典について必要以上の引用は避け、許諾・引用根拠の不明な台本は非公開評価用に限る。

## 2. 編集会議 — Editor
原典を読み、少なくとも3つの異なる論点候補を可能な範囲で比較する。数合わせや同じ発言の言い換えは禁止。良い論点は「知らなかった事実」「意外な思想的対立」「視聴者が自分で考えたくなる問い」が具体的にあり、内容に必要な尺（60〜90秒程度も積極的に検討）で一つの議論が閉じ、註釈が理解を深められるもの。尺は目安で、意味を削って合わせない。素材不足なら別章・教材へ。採用案だけを成果にし、別論点を混ぜない。

既存の同一発言・同一の結末を使ったクリップは、別の価値がなければ棄却。誰に何を持ち帰らせるか、他の切り抜きと何が違うか、原典のどの言葉で回収するかを決める。過去の本人評価と市場実測は区別し、視聴者仮説を実績として書かない。必要なら My Portal の動画制作・フック設計・対象視聴者モデルを参照し、利用できた実際の版のみ記録する。

## 3. 台本を組む — Scriptwriter
フックは異なる仕組みの原典引用2〜3個。同じ共通本編で全ての約束を回収できること。誤解を誘う抜き出し・タイトルで煽るだけのフックは禁止。
- QUOTE（フック）: 先に面白い発言。発言者と英日字幕。
- CONTEXT: 女性編者声でいつ／どこで／何への発言かを短く紹介。
- QUOTE: 原典の主張を展開。逐語英文＋忠実な和訳、対応する語句を同色強調。
- ANNOTATION: 女性編者声で背景・思想・歴史・語学のうち理解を変える知識を追加。原典の言い換えだけは不可。
- QUOTE: 発言に戻り論証・結論・問いを回収。必要に応じて註釈と交互に続ける。

引用と註の同時表示は禁止。原典の声が主役。引用の留保、反語、ユーモアを保ち、補足を増やすために発言の意味を改変しない。映像は studio-catalog.json の portrait/archive/title/contrast/timeline/concept から意味に合うものを選ぶ。映像だけ見ても論点が分かる構図、実在史料、図解の具体的項目、出典と年次、音響の変化を各セグメントに記述。題材固有の表現を優先して同じ演出を機械的に繰り返さない。

brief.json は studio-brief.example.json を参考に新規作成。引用ごとに原文全体と意味句別の対訳・対応ハイライトを持たせる。未調達の素材は予定パスと「要調達・権利未確認」の明示（rightsReviewed=false）を入れる。未計測の時刻を創作しない。台本段階では cue-audio と予定音源パスを指定し、原音声/TTS境界を確認した後に measured へ変更可。声を混同しない。publication.approved は false。現時点でオリジナル録音を検証できていなければ originalAudioChecked=false、audioKind=synthetic を仮の朗読計画とする。

## 4. 独立編集審査 — Reviewer
可能なら別エージェントに検討させる。利用できない場合は同じエージェントの独立した見直しで行い、別エージェント実行と偽らない。以下は単なる自己採点でなく、実際の本文・前後文脈・史料を読んで指摘を残し、問題があれば修正して再確認する。
- 原典忠実性: 発言者、時系列、語義、引用の前後、留保、訳。
- 視聴価値: 初見でも何が面白いか、他の論点候補より採用する理由、フックと結末の一致。
- 註釈価値: 引用の繰り返しではない追加知識と裏付け。事実と解釈を分離。
- 演出: 字幕分割、役割の切替、情報密度、素材と論点の一致、音声と画面の主従。
- 未確認事項: 原録音・権利・資料・音声・尺・利用できないツール等を隠さない。

editorial.scriptReview（brief内）に selection, rejectedAngles, contextRisk, hooks, annotations, unresolved を残す。hooks は全フックの id、promiseCheck、tradeoff。annotations は全編者註の id、addedKnowledge、basis（確認した資料/教材の具体的参照）、limitations。rejectedAngles は実際に比較した論点と不採用理由、比較できなければその理由を unresolved に残す。構造検査はレビュー内容の真実性や作品の合格を保証しない。

## 5. 台本提出・制作引継ぎ
```sh
npm run short:studio:check -- productions/<clip-id>/brief.json
npm run --silent short:script:export -- productions/<clip-id>/brief.json > productions/<clip-id>/script.md
```
export は同じJSONからフック比較、共通本編の発話・和訳・画面指示、字幕分割、編集審査、未調達素材一覧と概算尺を生成する。ファイルが欠けていても台本の構造・出典チェックはできる。概算尺は実測時刻ではない。検査が落ちたら台本を修正する。既存のbriefを無断上書きしない。

ユーザーに提示するのは完成した台本（候補の羅列で終わらない）、使用原典と論点、フック2〜3案、映像演出、未確認事項。本人の指示が台本だけならここで終える。動画まで依頼された場合は Studio v2 の素材調達、実音声/字幕タイミング、--media、レンダリングへ続く。台本の検査PASSは素材調達完了・映像品質・公開承認とは別。
