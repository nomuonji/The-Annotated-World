# UI visual identity research — 2026-11-26
Status: research / hypotheses, NOT design acceptance. PR #56 is held following owner feedback that the design system looks cheap. No further production UI changes in this research cycle.
## Diagnosis from actual render
Baseline PR 56 at 30d6894, CI artifact 15077832359, run 45733964991: inspected dark desktop library, words, topics, chapter reader and mobile home/library. All automated checks passed; that is not artistic approval.
- Library: room illustration bounded by rectangle, a second heading block, then a wide search rectangle, two adjoining tabs, another bordered filter row and a catalogue divider. Repeated horizontal dividers with similar weight dilute focal hierarchy. The two document entries are below several layers of control chrome. Brass-colored outlines change paint but not this structure.
- Words and topics: room banner + same search strip + regular repeating records. Each uses the same near-uniform background/spacing, little relation between a term, its meaning, its use and neighboring entries. Serial labels are visually prominent relative to actual reading task; an arbitrary serial has no editorial value if unstable or unhelpful.
- Reader: tiny rectangular buttons on an otherwise normal two-column reading tool; several borders and separators with equal contrast. Changing button corners does not create an identity. Preserve the tested mobile pin/dock and reading behavior; don't add more chrome.
- Header: small icons, numbers and labels on seven equally weighted destinations. Numbering is not a substitute for navigation hierarchy. Existing character and source thumbnails carry much more identity than controls. Mobile stacks banner, repeated heading and search apparatus before actual material.

## Candidate visual grammar
Core: annotation is an act of directing attention, exposing relationships, and comparing words/meaning. A reading object can be a printed page under study, an index of evidence, a film excerpt, rather than a mystical instrument. The site is not an antique-librarian dashboard or a game inventory. Three independent design hypotheses for controlled prototyping:
A / editorial contrast: dark ink/cream paper or reverse, one deliberate rose signal, variable scale title/display/reading type, asymmetric publication composition. Separate actual reading content from selection. No extra serial without meaning.
B / material mechanics: selected source or chapter is a film strip/book leaf; edge, overlap, index tongue, paper thickness and direction express selection. Index shows selected word, examples and meaning on one composition with actual data. No fake gauges or unnecessary panels.
C / intellectual relationships: active passage/term generates a focused margin, nearby context, evidence connections. Lines/brackets have endpoints and real semantic role; active selection reveals information rather than another decorative box. No fabricated relationships.
All are hypotheses, not user approval. Combine only if composition warrants; maintain distinct discovery, catalogue, index and intensive reading surfaces. Use existing fonts first, stronger contrast and real whitespace, no texture budget spent on every component. 
## Design before system
- Create a visual reference inventory of actual screenshots, at least one functional state pair per pattern: inactive/active list, search before/after, reader annotations off/on; note typography hierarchy, extent of boundaries, relative image area, negative space, geometry, layer order, timing and why. Reference no copied assets.
- Make independent same-content compositions for A/B/C at 1440 and 390, first on library + word index + reader; use current baseline and exact source text/thumbnail. No production edits. Compare at full size and at thumbnail scale with art hidden and monochrome; if identity disappears, reject. Reject variants that merely recolor existing widgets or add generic numbers. 
- Evaluate primary task (find and open a real source; find term and usage; switch reading state), first visible actual content, keyboard, contrast, 320px and no horizontal overflow. Maintain native semantic controls and prior pinned translation/video area; no forced transitions. Measure actual rather than invented timings. 
- Compare screenshots side by side; distinguish design taste from technical pass. Derive reusable component contracts AFTER a good complete composition is accepted; don't prematurely standardize every control.
- Owner visual decision before rollout. PR56 technical pass is not approval.
