# Pilot 008 — BGM audibility and mobile caption density

制作日 2026-11-20。最新の直接フィードバック：**「BGM聞こえない。字幕が読みづらい。スペースがやたら開いててもったいない」**。

**状態**：完成MP4（81秒弱）と再編集ソースを当該チャットで提供。編集中のプロトタイプであり公開・配信・使用者採用の判断はまだない。元2026年動画の映像・音声を使用しておらず、合成英語ナレーションと2011年のŽižek写真、議論に対応する史料画像を使用。

## 失敗の実測と変更
### 1. 音が聞こえない
- V7 BGMの平均RMS **−41.86 dBFS**、V7の英語音声は約−20.44 dBFSで、音楽が約21.4 dB小さかった。ダッキングに加えて音源そのものもほぼ低周波と効果音のみだった。
- V8は96 BPMの新たなオリジナル合成音楽（和音パッド、ピアノ風のミッドレンジのプラック、ベース、ハイハット/スネア、意味上の転換点の短いSE）を生成。外部の曲・サンプルは使用しない。
- V8 BGM **−29.70 dBFS RMS / −27.6 LUFS**、英語音声 **−20.44 dBFS RMS / −17.2 LUFS**。音声の方が約10 LU強い設定。声中は緩やかにダッキング、問いの部分は短く落とす。V7対比BGMの実効RMSは約 **+12.2 dB**。最大の音量差だけで判断せず、BGM単独試聴と最終音声の主観聴取が必要。
- 生成した独自BGMはコードで再生成可能。声や元講演を模倣しない。

### 2. 字幕が読みづらい
- V7は字幕英語25〜32px／日本語24〜29pxの狭い中央寄せカラム（約468px幅）で、無用な改行と英語・日本語の大きな間が発生していた。
- V8は英日とも**36〜38px**、左揃え、テキストブロック幅**508px**、カードの左右 x=44..596 に拡大。英日間の余白を**14px**に短縮。二重の全文字幕と17組の色付き対応ハイライトを維持。
- 字幕ブロックの最大下端をV7の約827pxからV8の**997px**へ伸ばし、下方170pxの暗い空き領域を解消。背景写真を画面下方まで見せる。
- V8のカード上端は動的に y588..768px、下端は997pxに固定。720×1280画面の下方283pxをSNS操作UI用に残す。アプリの全端末で保証される「安全領域」ではなく、Shorts/TikTok/Reels実機UIテストは未実施。右側UIを避けるためxは596px以下にする。

### 3. 作品の価値を維持
- 内容、英語音声速度、元教材の議論、20発話ビート、17色対応箇所は**V7から無変更**。思想解説を情報量の少ない映像へ置換していない。
- ビート単位の字幕、原典の留保や辛辣なジョーク、本人肖像・関係史料を保持。字幕カードの高さだけを実際の文字量に合わせて可変にし、固定空白を作らない。

## 再現と検証
- MP4: `720×1280 20fps / H.264 + AAC 48kHz stereo / 80.75 s`。
- 全編FFmpegデコード成功、20ビートの字幕カードを描画、英語／日本語の字面が領域内に収まることを検査。英日ペアは`linked-pairs.json`、字幕`captions-en-ja.srt`。
- 音声のBGM・ナレーション・最終mixを分離して検査。測定は「BGMが前版より確実に大きい」ことを示すが、**人間が音を試聴して音楽的品質や聴き取りやすさを評価したとは言わない**。
- 制作ZIPには `render.py` / `sound-design.py` / `prepare-voice.py` / 英語音声MP3 / 使用写真 / 完成動画 / BGM単独試聴サンプル / 画像プレビュー / 出典台帳を同梱。メディア本体はGitHubにコミットしていない。
- 写真のライセンスと原文テキストの元音声との照合、各アプリでのUI被り、客観的な視聴維持率を最終公開前に確認する。

## プロジェクト原則
字幕をUIから逃がすことを優先しすぎて、使えるキャンバスを空けない。**視認性・画面占有率・プラットフォームUI非干渉の3条件を一緒に最適化**する。音量正規化した音声の陰でBGMが測定上ほぼ無音になったまま完了扱いにしない。自己採点のtechnical PASSは本人の「聞こえない」「読みにくい」という編集評価への反論にならない。
